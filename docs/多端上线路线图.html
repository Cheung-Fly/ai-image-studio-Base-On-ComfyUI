AI 生图工坊 · 多端上线路线图

网页端 / 微信小程序 / 桌面软件 —— 三种壳共用同一套云端后端 API
核心判断：不要做三个项目。三端只是前端形态不同，真正要先完成的是把 FastAPI + Celery + Redis + ComfyUI(GPU) + LLM 部署到云端并通过 HTTPS 域名对外开放；之后网页、小程序、桌面软件都向同一个 https://你的域名/api/ 发请求。推荐顺序：网页端 → 小程序 → 桌面端。

一、总体架构（上线后）

示意图：服务可合并部署在同一台 GPU 服务器（学习期省钱），用户量上来后再把应用层与 GPU 层拆分。

二、所有端的共同地基（只做一次）

事项具体操作说明
后端 + GPU 上云云 GPU 服务器用 docker-compose 启动 api/worker/redis，ComfyUI 常驻；llama.cpp 可同机或独立必须 不能跑在个人电脑
域名 + ICP 备案买域名 → 国内服务器控制台提交 ICP 备案（个人可办，约 1~3 周）必须 用境外服务器可免备案但访问慢，且小程序不支持
HTTPSNginx 反向代理 + Let's Encrypt 免费证书（或云厂商免费 SSL）必须 小程序与现代浏览器强制
用户系统注册/登录、JWT 鉴权、按用户限流与配额（每日生图张数）必须 当前项目无登录，需新增 auth 模块
数据库与存储升级SQLite → PostgreSQL；图片从本地磁盘 → 对象存储 OSS/COS + CDN必须 多用户并发与弹性扩容
跨域 CORSFastAPI 加 CORSMiddleware，只放行你的前端域名必须
安全与可观测内部服务（ComfyUI/llama-server）只监听内网、密钥用环境变量、日志与错误监控必须

三、三个端分别要做什么

① 网页端

最先做，求职演示足够
  • 现有 index.html 完善为正式前端（或用 Vue/React 重写）
  • 静态文件交给 Nginx 或对象存储静态网站托管
  • API 地址改为 https://域名/api
  • 加登录页、生成进度轮询、画廊页
  • 部署最简单，迭代最快，建议作为求职作品主形态

② 微信小程序

复用后端，前端重写
  • 注册小程序账号，用 WXML 或 uni-app/Taro 重写页面（HTML 不能直接用）
  • 管理后台配置 request/downloadFile 合法域名（须 HTTPS+已备案）
  • 登录走微信授权 code2session
  • 学习演示：用「体验版」+ 添加体验成员（最多30人），可免正式审核跑通
  • 正式发布：AIGC 类目对个人主体限制多，通常需企业主体 + 生成式 AI 备案

③ 桌面软件

推荐 Tauri，轻量
  • 用 Tauri（包体约 10MB）或 Electron（生态成熟、约 100MB+）把前端包成 .exe
  • 形态：客户端只做界面，连云端 API；不要把 13GB 的 ComfyUI/模型塞进安装包
  • 用 NSIS 做安装程序，配代码签名证书（否则 SmartScreen 拦截）
  • 可加自动更新；通过官网/GitHub Releases 分发

四、建议的演进时间线

M0 · 本地全链路跑通（当前）本机 FastAPI + Celery + Redis + ComfyUI，冒烟测试通过、真实出图
M1 · 云端 LLM 接入（进行中）llama.cpp 部署 P4 + SSH 隧道 + /api/optimize-prompt 提示词扩写
M2 · 后端整体上云GPU 服务器跑 ComfyUI+后端，先用 IP:端口 让公网访问 Swagger 验证
M3 · 网页端正式上线域名备案、Nginx+HTTPS、用户登录、对象存储、PostgreSQL
M4 · 小程序先出体验版用于求职演示；有企业主体后再走正式审核与备案
M5 · 桌面版Tauri 打包前端连云端 API，签名后发布安装包

五、合规红线（面向国内公众用户）

文生图属于「深度合成」且属于「生成式 AI」，正式对公众提供服务前：

  • 完成 ICP 备案（域名）与 生成式人工智能服务 / 深度合成算法备案（通常要求企业主体）；
  • 接入内容安全审核：提示词文本审核 + 生成图片审核（云厂商均有内容安全 API）；
  • 对 AI 生成图片添加显著标识/隐式水印（《人工智能生成合成内容标识办法》要求）；
  • 求职/学习阶段不受影响：本地运行、网页演示给面试官、小程序体验版加白名单成员，都不需要正式备案。

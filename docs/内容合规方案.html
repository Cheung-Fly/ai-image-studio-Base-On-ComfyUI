AI 生图工坊 · 内容合规方案

三道闸门 + AI 生成标识 + 备案资质 —— 让平台"生成不了、展示不出、传播可溯"违规内容
核心思路：合规不是一个功能，而是一条贯穿全链路的流水线 —— 事前拦提示词（输入审核）、事中约束模型（负向提示词）、事后审图片（输出审核），再叠加AI 生成标识与备案/人审/日志。求职阶段只需把"输入+输出两道审核"工程化跑通，正式上线才需要完整资质。

一、全链路审核流程（标注在现有架构上）

示意图：两道审核闸门分别在 API 层（提交前）与 worker 层（出图后）；模型本身无法被"命令"不画违规内容，必须靠输入、输出双侧兜底。

二、三道闸门详解

① 输入：文本审核

  • 位置：api/generate.py 提交任务前
  • 本地敏感词/正则兜底（零成本、防断网）
  • 云文本审核 API：涉黄涉政、暴恐违法、未成年人
  • 用已有 LLM 做语义判断（零成本第一道）
  • 云厂商可识别拼音、拆字、谐音、emoji、英文绕过
  • 命中 → 拒绝并记录，不消耗 GPU

② 模型：负向约束

  • 位置：services/workflow.py
  • 负向提示词固定追加：nsfw, nude, blood, gore, violence, minor
  • 扩散模型无"安全开关"，此项仅降低概率
  • 不能作为唯一手段，必须配合输出审核
  • 可选经过安全对齐的底模

③ 输出：图片审核

  • 位置：workers/tasks.py 落盘后、入库前
  • 云图片审核：色情、性感、暴恐、政治人物、血腥、违禁
  • 命中 → 任务 blocked、图片不展示
  • 存疑 → 人工复审
  • 参考成本：通用图片审核约 1.5~2.7 元/千次

三、AI 生成标识（法规强制，2025-09-01 起施行）

类型做法在你项目里的实现
显式标识 图片适当位置添加用户可明显感知的提示（"AI 生成 / AI Generated"） Pillow ImageDraw 在右下角绘制文字角标（你已有 Pillow）
隐式标识 文件元数据中写入：内容属性信息、服务提供者名称/编码、内容编号 Pillow PngInfo 写入 PNG 元数据；进阶用 C2PA / 不可见数字水印

六、学习/求职阶段的最小实现（不花钱）

  • 第1步 写 DevModerationProvider：内置几十个敏感词做本地拦截，其余放行，把"审核拦截→任务 blocked"的工程链路跑通；
  • 第2步 用你已有的 LLM（llama.cpp）做文本审核：让它判断 prompt 是否违规并按 JSON 返回，零成本；
  • 第3步 云厂商（阿里云/腾讯云）内容安全新用户免费额度内测试真实文本+图片审核，截图写进作品集；
  • 第4步 Pillow 实现"AI 生成"角标 + PNG 元数据，满足标识要求；
  • 第5步 面试串讲："输入-输出双侧机审、存疑转人审、AI 标识、违规熔断、日志留存"。
本地运行、课堂演示、给面试官看 Demo 均不触发备案要求；备案是"向境内公众提供服务"时才需要。

七、技术选型：为什么用云审核 API

方案优点缺点
纯敏感词库免费、快不懂语义、变体绕过、图片完全无法审
开源模型（Nudenet 等）免费、可本地部署只覆盖裸露等单一场景，政治/暴恐缺失，要自己运维 GPU
云内容安全 API场景全、更新快、按次计费约 1.5~2.7 元/千次、免运维依赖网络、需 HTTPS 与密钥管理
